## 🚀 使用方法

### 1. Issue作成時
1. 適切なテンプレートを選択
2. テンプレート内容をコピー
3. 新しいIssueを作成してペースト
4. 必要項目を入力

### 2. Pull Request作成時
1. 関連するIssueを確認
2. 適切なPRテンプレートを選択
3. テンプレート内容をコピー
4. 新しいPRを作成してペースト
5. 修正内容とテスト結果を記入

### 3. ラベル設定
各テンプレートに推奨ラベルが記載されています。

## 📊 テスト管理フロー

### 単体テスト
1. **Issue作成**: 各API/関数に対してテストIssueを作成
2. **テスト実行**: テスト実行結果をIssueに記録
3. **不具合発見**: 不具合情報をIssueに記録
4. **PR作成**: 修正内容をPRで管理
5. **レビュー**: コードレビューとテストレビューを実施
6. **マージ**: 修正完了後にマージ

### 結合テスト
1. **Issue作成**: モジュール間結合テストのIssueを作成
2. **結合確認**: データフローと結合部分の動作確認
3. **問題発見**: 結合問題をIssueに記録
4. **PR作成**: 結合部分の修正をPRで管理
5. **統合確認**: 全体の整合性確認
6. **マージ**: 結合完了後にマージ

### 総合テスト
1. **Issue作成**: エンドツーエンドテストのIssueを作成
2. **システム確認**: システム全体の動作確認
3. **性能・セキュリティ**: 非機能要件の確認
4. **PR作成**: システム全体の修正をPRで管理
5. **最終確認**: 本番準備の確認
6. **本番リリース**: 総合テスト完了後にリリース

## 🏷️ 推奨ラベル

### 共通ラベル
- `testing` - テスト関連
- `bug` - バグ修正
- `enhancement` - 機能改善
- `priority-high` - 高優先度
- `priority-medium` - 中優先度
- `priority-low` - 低優先度

### テスト固有ラベル
- `unit-test` - 単体テスト
- `integration-test` - 結合テスト
- `system-test` - 総合テスト
- `performance` - 性能テスト
- `security` - セキュリティテスト
- `e2e-test` - エンドツーエンドテスト

### 状態ラベル
- `ready-for-review` - レビュー準備完了
- `in-progress` - 作業中
- `blocked` - ブロック状態
- `needs-info` - 情報不足

## 📋 マイルストーン

### 推奨マイルストーン
- `単体テスト完了` - 全単体テストの完了
- `結合テスト完了` - 全結合テストの完了
- `総合テスト完了` - 全総合テストの完了
- `本番リリース準備` - 本番リリース準備完了

## 👥 アサイン推奨

### 単体テスト
- **担当者**: 各API/機能の開発者
- **レビュアー**: 他の開発者、テストリーダー

### 結合テスト
- **担当者**: 結合部分の開発者
- **レビュアー**: アーキテクト、テストリーダー

### 総合テスト
- **担当者**: システム全体の責任者
- **レビュアー**: アーキテクト、セキュリティ担当、運用担当

## 🔄 自動化

### GitHub Actions連携
- CI/CDパイプラインでテスト自動実行
- テスト結果の自動コメント
- テスト完了時の自動ラベル付与

### 通知設定
- テスト失敗時の通知
- レビュー完了時の通知
- マージ完了時の通知

## 📝 カスタマイズ

各テンプレートは、プロジェクトの要件に応じてカスタマイズ可能です。

### カスタマイズ観点
- 項目の追加・削除
- ラベルの変更
- 承認フローの変更
- 通知設定の変更
